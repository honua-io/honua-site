The most powerful thing a GIS server can be is boring.

Spatial work earns its reputation for difficulty honestly. Projections, predicates, topology, and the cartography that makes a map true. None of that should leak into how the thing runs. A geospatial server should deploy like any other container, price like any other infrastructure, and answer a where-question the day it's asked without ceremony. The craft of the map was never the problem; everything underneath it should be too dull to mention.

Five principles, and what they make possible.

The first five guide the product. The final card is the outcome they are meant to create. Follow the links for current evidence and limits.

01

Cost scales with workload, not adoption

Infrastructure you already know how to price, and a flat license. No named-user seats, request credits, or data-volume billing. Adding a user creates no Honua seat fee; 2026.1 licensing is disabled and serving-unit bands are neither measured nor enforced. Capacity-band licensing is 2026.2 intent.

The pricing model
02

It runs like the rest of your stack

One lightweight container beside the PostGIS you already run, with documented paths for Kubernetes and ECS plus serverless evaluation paths. Upgrades follow your normal redeploy process rather than a separate GIS installer. On an existing database the server holds contract migrations, the ones that drop or rename schema objects, until an operator explicitly approves them, and a server image that includes the schema-reader check refuses to start on a schema with migrations it does not recognize, so qualify the image you would roll back to. See the upgrade and rollback guide.

03

Standards are the exit, not the checkbox

Supported desktop GIS, QGIS, Excel, Power BI, and browser workflows connect through familiar interfaces. The public matrix shows what works, what needs adaptation, and where standards preserve an exit.

04

Spatial work belongs to everyone

Developers can work with curl, analysts can use familiar tools, and spatial professionals can spend more time on analysis. The server should not turn every contributor into an accidental administrator.

05

Automation proposes. Policy decides.

Private-beta operator tools prepare plans, dry runs, and recorded actions. Models propose; explicitly configured policy may permit deterministic low-risk actions. Risky and irreversible changes remain approval-gated, and broader autonomous recovery is planned.

+ · What this makes possible

The craft is not the cage

Making geospatial ordinary doesn't make spatial expertise less valuable. It makes it count for more, because when the plumbing disappears, the judgment is what's left.

See supported QGIS workflows

It stops being rationed.

When geospatial becomes ordinary, more teams can ship maps, more dashboards can answer where, and more questions can be handled in the tools people already use. Making GIS boring was never about less of it. It is how spatial expertise reaches more work.
