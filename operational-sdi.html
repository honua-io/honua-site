Operational SDI vs. static publishing SDI.

Static publishing SDIs put read-only cloud-native files (GeoParquet, PMTiles, COG, STAC) in object storage or query them from an analytics warehouse. That pattern is fast and low-cost for read-only dissemination, but it does not replace an operational GIS server. An operational SDI runs the live transactional workflows that produce those datasets in the first place.

Read-only files in object storage or warehouse tables; edits happen upstream in another system and require a separate rebuild pipeline.

Where each fits—and why agencies need both.

Choosing between static files and a live server is a false binary. Public agencies run both workloads on the same authoritative data.

01 · Static publishing fits

Immutable archives and open-data downloads.

When a dataset changes quarterly—census boundaries, annual imagery mosaics, historical hydrology—publishing GeoParquet, PMTiles, and COG behind a CDN gives browsers and data scientists fast range reads with minimal server load.

02 · Operational SDI fits

Live registries, permits, utilities, and response.

When staff edit parcels, log 311 requests, update road closures, run geoprocessing jobs, or enforce per-department permissions, you need a live transactional server that speaks the protocols your desktop, web, and automation clients already use.

03 · Together in one platform

Edit in the live server, serve public reads from tiles and files.

Honua keeps PostGIS as the operational system of record while serving vector tiles, STAC collections, and cloud-hosted COGs directly—and extends toward CDN-backed Cloud-Native Exports so public-scale portals share the same governance boundary as live editing.

Cloud-native delivery and STAC / GeoParquet / PMTiles interoperability.

Interoperability with open cloud-native catalogs matters because spatial data outlives any single vendor. Here is what Honua serves today and what remains on the roadmap.

Implemented today

Live STAC, vector tiles, and cloud-hosted COGs.

Honua serves STAC API endpoints, vector tiles (MVT/PMTiles), OGC API Tiles, and HTTP-range COG rasters from object storage. The public Maui parcel lookup sample ↗ demonstrates browser-side reads over a paired PMTiles + GeoParquet publication.

Not yet · Roadmap (2026.1)

Self-describing Cloud-Native Exports.

Server-managed Cloud-Native Exports—producing a STAC collection document, README, AGENTS.md, style, thumbnail, and paired PMTiles + GeoParquet files served from the public data path—are not yet shipped as a release capability; implementation is tracked across honua-server#8259 ↗, #8267 ↗, #8268 ↗, and #8260–#8265 ↗.

Not yet · Roadmap (post-2026.1)

Scheduled refresh and bucket-layout STAC catalogs.

Automated scheduled Export refresh when source layers change (honua-server#8271 ↗) and a read-only STAC catalog over published layers emitting GeoParquet/PMTiles extracts in a standardized catalog-first bucket layout (honua-server#4718 ↗) are not yet implemented and sit on the post-2026.1 roadmap.

Sovereignty, model neutrality, and engine independence as governance.

For public-sector and regulated buyers, sovereignty is not a marketing slogan—it is an architectural boundary you can verify in your own cloud account.

01 · Your cloud, your jurisdiction

Data never leaves your deployment.

Honua runs self-hosted in your cloud account or on-premises against your PostGIS database and your object storage buckets. There is no required vendor-hosted control plane, and source records stay inside the legal jurisdiction you configure.

02 · Model & client neutrality

Bring any MCP client or self-hosted model.

Honua publishes MCP discovery and query tools over standard HTTP and stdio transport (geospatial-mcp ↗). Connect commercial frontier models, private VPC-hosted models, or local open-weights models without changing your GIS server or locking your agency to one AI provider.

03 · Server-enforced guardrails

Policy and approvals stay out of the prompt.

Credentials, RBAC, tool permissions, and approval gates are enforced by Honua's server and declarative spec-apply workflow. Controlled operations automation (Pilot access) gathers evidence first, defaults to reviewable proposals, and emits redacted structured records for every action.
