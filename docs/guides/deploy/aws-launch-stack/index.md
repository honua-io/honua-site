# Install Honua in your AWS account (Launch Stack)

You'll install Honua into your own AWS account with one CloudFormation stack, know what it creates and what AWS charges you for it, and know how to remove it cleanly.

**Who this is for:** [design partners](https://honua.io/design-partners.html). The Launch Stack is how we install Honua with you during step 3 of the programme. This is a preview install. Honua supplies a versioned template link and compatible server image digest after the release candidate and clean-install checks pass.

**Customer-operated.** Everything runs in your AWS account, under your control, on your AWS bill. Honua does not host or operate your install and has no access to it unless you grant it.

## How it works

The Launch Stack is a native AWS CloudFormation template. With the default settings, it creates resources directly without Terraform or a build pipeline. You open the link in the CloudFormation console, review the template and parameters, and create the stack. The install also fetches the watchdog code and the Console files that the template version pins from Honua's template bucket, and verifies each SHA-256 checksum before use.

The form opens with one group, **Your install**: `AdminEmail` and an optional `DomainNames`. That group is most of what you enter. The **Presets** group (`Size`, `Availability`, `Protection`, `IdentityProvider`) and the groups labelled **Advanced** have defaults that install a complete, protected stack untouched. The **Your install** fields show the parameter name in brackets; every other field is listed by its parameter name, as in this guide. For this preview install you also set `ServerImageUri` to the image digest Honua gives you, any existing CloudTrail trail ARN from your account check, the certificate for your own domain if you use one and, outside us-east-1, the companion web ACL values and `WatchdogMode=Off` (see Install below).

Keep `AiProvider=None` unless you intend to turn on the optional Studio assistant in your account ([Optional Studio assistant](#optional-studio-assistant)). That assistant is separate from agents. The install template creates no agent resources and has no agent parameters: agent preview is a separate stack, created later with its own install checks and approved inputs.

## Choose a region

- **US East (N. Virginia), `us-east-1`: one stack.** It creates its own CloudFront web ACL (AWS WAF). This is the recommended region for design partners.
- **US East (Ohio), `us-east-2`, or US West (Oregon), `us-west-2`: two stacks.** CloudFront only accepts a web ACL from `us-east-1`, so you first create the companion `waf.yaml` stack **in us-east-1**, then pass its `WebAclArn` and `WebAclMetricName` outputs to the main stack in your region. The main stack checks that web ACL and refuses one that is older or weaker than its `Protection` preset, so create and later update the companion stack from the same template version, companion first. Install the main stack with `WatchdogMode=Off` (see [the watchdog](#the-watchdog)).

Other regions are not supported yet: the template relies on CloudFront private VPC origins, which AWS offers only in some regions and Availability Zones.

## Before you start

- **An AWS account you control.** Start with a non-production account. Your user or role needs permission for every service the template uses (VPC, ECS, Elastic Load Balancing, Application Auto Scaling, RDS, S3, CloudFront, WAF, IAM, Secrets Manager, KMS, CloudWatch, SNS, SQS, EventBridge, Systems Manager Parameter Store, Lambda, Cognito, CloudTrail, GuardDuty, AWS Backup, Route 53 (a health check, plus DNS records if you use a hosted zone), AWS Budgets in us-east-1 and, if used, ACM and AWS Batch) and to create those services' AWS service-linked roles. You will acknowledge IAM resource creation; the template creates no named IAM roles and no administrator policies.
- **Service quotas** in the target region: Fargate On-Demand vCPU, one Elastic IP and NAT gateway (two with `Availability=High`), RDS instances, CloudFront distributions and VPC origins, and WAF web ACLs. The setup function and the watchdog each reserve one Lambda concurrency slot, and AWS keeps 100 unreserved, so the account's Lambda concurrency quota must be at least 102 (101 with `WatchdogMode=NotInstalled`); new accounts often start lower. The CloudFront managed prefix list uses 55 security-group rule units, so keep the default quota of at least 60 rules per direction. Increases are not immediate; request them early.
- **An account protection check before launch.** The stack uses the account's existing GuardDuty detector in the region by reference and never changes or deletes it; it creates a detector only when there is none. A detector the stack finds must be enabled with Runtime Monitoring on, or the create or update that first uses it fails with a message saying so. Identify any existing CloudTrail trail with your AWS administrator and supply it through `ExistingCloudTrailArn`: an empty value adds a second trail, which bills a second copy of management events. In an account with no detector yet, create one stack at a time: if the first create rolls back, the detector it created goes with it. Honua supplies the account preflight with the approved install instructions; the console link cannot run it for you.
- **The template link and server image digest from Honua.** The template is larger than the console's inline upload limit, so it is always opened from an HTTPS link. The image is always given as a digest (`registry/repository@sha256:...`); the stack refuses a tag.
- **An administrator email address and authenticator app.** By default, `IdentityProvider=Cognito` creates sign-in in your AWS account and invites `AdminEmail`. You do not need an existing identity provider. To use your own provider, choose `IdentityProvider=External` and configure the external OIDC parameters below. `AdminEmail` also receives operational alarms and, in us-east-1, budget notices unless you set a separate `OpsNotificationEmail`.
- **Your own domain only:** the site sends HSTS with `includeSubDomains`, so if you use a zone apex, confirm that every subdomain already serves HTTPS.

## Operation key ring

Honua encrypts the credentials of long-running operations with an operation key ring, which is protected by a secret held outside the database. Leave `OperationKeyRingSecretArn` empty and the stack generates that secret for you: a random Secrets Manager secret, encrypted with the stack key (or `CustomerKmsKeyArn` when you set one), that only the server and Batch worker can read. Its ARN is the `OperationKeyRingSecretArn` stack output, and it is retained when the stack is deleted.

Back the secret up with your database backups and restore them together. A ring protected with one secret cannot be read with another, so never change, rotate or delete it while the database, or a snapshot you may restore, exists: the server refuses to start with a different secret. Do the same for the stack's generated connection-encryption secret (the `MasterKeySecret` resource): it protects stored data-source credentials, and AWS Backup does not back up secrets.

**Bring your own certificate instead (optional).** To protect the ring with a certificate you own, create it before installing, on a trusted workstation with OpenSSL and the AWS CLI, in the deployment account and region:

```sh
umask 077
mkdir honua-keyring && cd honua-keyring
openssl req -x509 -newkey rsa:3072 -sha256 -nodes -days 3650 \
  -subj '/CN=Honua operation key ring' -keyout key.pem -out certificate.pem
openssl pkcs12 -export -inkey key.pem -in certificate.pem -out keyring.p12 -passout pass:
openssl base64 -A -in keyring.p12 -out keyring.txt
aws secretsmanager create-secret --region YOUR_DEPLOYMENT_REGION \
  --name honua-operation-keyring \
  --description 'Honua durable operation key-ring protection' \
  --secret-string file://keyring.txt \
  --query ARN --output text
```

Set `OperationKeyRingSecretArn` (in **Advanced: encryption, backups and retention**) to the returned ARN. Use the default `aws/secretsmanager` encryption key. Keep an encrypted recovery copy of `keyring.p12` with your database backups, then delete the working files under your organisation's policy. Keep the same certificate, and keep `OperationKeyRingSecretArn` set, on every update, scaling change and restore: clearing it switches the stack to a generated secret, and the server then refuses to start because the existing ring is wrapped with your certificate. Never put key material in stack parameters, a Launch Stack link or source control.

## Install

- **Step 1.** **Other regions only:** open the `waf.yaml` link in **us-east-1**, create that stack, and copy its `WebAclArn` and `WebAclMetricName` outputs.
- **Step 2.** Open the Launch Stack link Honua sent you. Check that the region in the console header is the one you chose.
- **Step 3.** Fill in the **Your install** group: `AdminEmail` and, if you want your own hostname now, `DomainNames` (empty serves the install at its `cloudfront.net` address; you can add a domain later). Also set `ServerImageUri` (in **Advanced: release artifacts**) to the digest from Honua; leave `EnableConsole` and `ConsoleBundleVersion` in that group at their defaults. If your account check found an existing CloudTrail trail, set `ExistingCloudTrailArn` (in **Advanced: protection overrides**); an existing GuardDuty detector is found without input. If you set `DomainNames`, also set `AcmCertificateArn`, or `HostedZoneId` in us-east-1 (in **Advanced: DNS, certificate and browser access**; see [Use your own domain](#use-your-own-domain)). Outside us-east-1, also provide `WebAclArn` and `WebAclMetricName` from the companion stack (in **Advanced: protection overrides**) and set `WatchdogMode=Off` (in **Advanced: watchdog**). Keep `IdentityProvider=Cognito` for default sign-in; External mode instead requires `OidcAuthority`, `OidcClientId` and `OidcClientSecretArn`. If the image is in a private Amazon ECR repository, also set `EcrRepositoryArns`. Leave everything else at its default.
- **Step 4.** Acknowledge IAM resource creation and create the stack. Wait for `CREATE_COMPLETE`. With `Size=Small` and `Availability=Standard` in us-east-1, our test installs took 18 to 33 minutes with the default Contain protection (the CloudFront distribution is usually the slowest step) and about 18 minutes with Watch. Larger sizes and `Availability=High` add database time. If a create makes no progress for 20 minutes, check the stack's Events tab for the first `CREATE_FAILED` reason, then the ECS service's events and stopped tasks.
- **Step 5.** Review the stack events and operational outputs. `WatchdogStatus` says whether the watchdog is installed and in which mode. Deletion protection is applied only after every other resource exists. Contain and Strict turn load-balancer deletion protection on and enforce database deletion protection. Watch turns load-balancer deletion protection off and honors `DatabaseDeletionProtection`. A failed first create is not blocked by deletion protection. If creation fails, follow the stack events. A stack an earlier template left in `ROLLBACK_FAILED` still needs the cleanup below. A failed stack does not support the update used for normal teardown.
- **Step 6.** Open `HonuaUrl` and check `/healthz/ready`. The template Honua publishes installs Console during stack creation: you upload nothing, and the `ConsoleUrl` output is where you sign in. If the stack has no `ConsoleUrl` output, the template version you were given carries no Console files and browser sign-in and approvals are not available yet; ask your Honua contact before going further. With Cognito, use the administrator invitation email's temporary password, choose a new password and enrol an authenticator app; MFA is required. The stack registers `OidcCallbackUrl` automatically. With External mode, register that exact callback with your provider before signing in; for a custom domain it is `https://YOUR_FIRST_DOMAIN/admin/auth/callback`. Sign-in fails until the external provider accepts it.
- **Step 7.** Confirm the AWS notification subscription email sent to `OpsNotificationEmail`, or to `AdminEmail` when that is empty; alarms reach nobody until it is confirmed. 
- **Step 8.** Create API keys for scripts and agents from your signed-in administrator session. Do not plan to read the generated administrator credential behind `AdminSecretArn`: it is sealed by default, so AWS refuses to return its value, and it is for recovery only (see [Recover administrator access](#recover-administrator-access)).

## What it creates

- A new VPC across two Availability Zones: two public subnets with one NAT gateway (two with `Availability=High`), two private subnets and restricted security groups. You can reuse an existing VPC instead.
- A CloudFront distribution in front of an **internal** load balancer, reached over a CloudFront private VPC origin. There is no public load balancer, the tasks have no public IP addresses, and the load balancer refuses requests that do not come from your distribution. AWS WAF protects the distribution.
- Honua server tasks on ECS Fargate (the Small preset uses 1 vCPU and 2 GiB per task) with CPU and request-count autoscaling between `MinTasks` and `MaxTasks`, deployment rollback and CloudWatch logs.
- An encrypted RDS PostgreSQL 16 database with PostGIS (20 GiB gp3, growing to 100 GiB, seven-day automated backups), single-AZ unless you choose `Availability=High`.
- Versioned, encrypted, private S3 buckets for files and job outputs, and generated secrets for the database, the administrator credential and connection encryption. The administrator credential is sealed: only task start-up can read it.
- Console, served at `/console` on the same domain from its own private, versioned S3 bucket. There is no Console container. `EnableConsole=false` installs the API only.
- A daily AWS Backup plan for the database and files.
- A rotating encryption key for application resources and the database. No key input is required; `CustomerKmsKeyArn` is an optional override that must be set at installation. The stack retains its key when removed, so encrypted data remains recoverable.
- Operational alarms and email notifications, CloudTrail audit logging, and GuardDuty runtime protection, using the account's existing detector when there is one. An existing CloudTrail trail must be identified before launch.
- An independent watchdog, installed by default in `NotifyOnly` mode: a Lambda function outside the server that checks the site once a minute and notifies you when a check fails, without taking any action (see [the watchdog](#the-watchdog)).
- Optionally, AWS Batch capacity on Fargate for managed geoprocessing jobs. Off by default; Batch has no idle charge.
- Optionally, a public-data bucket served read-only at `/data/*` (`EnablePublicData=true`). Off by default. On, a server that supports public export also publishes there; see [Parameters](#parameters).
- A lookup Lambda function for the CloudFront prefix list, supported Availability Zones and settings validation, and a short-lived function that unpacks the Console files during create and update.
- With default Cognito sign-in, an administrator-only user pool with mandatory MFA and the Plus plan and threat protection, a hosted sign-in domain, an authorization-code client and an `admin` group. A separate Lambda copies the generated client secret into Secrets Manager; credentials are not sent to Honua.

Shared state lives in PostgreSQL.

Geoprocessing job outputs are written to task scratch space in this release, not to the job-outputs bucket, so they are lost when a task or job is replaced. Download results you need to keep.

## The watchdog

The watchdog runs in your account, separately from the Honua server, so it can still notify you when the server is down. Every minute it checks the stack's own `cloudfront.net` address, including the uncached `/healthz/deep` database and catalog check, and notifies the same address as the other alarms when a check fails. In `NotifyOnly` it never restarts or changes anything. Because it checks the CloudFront address, a custom domain whose DNS is not set up yet is not reported as an outage.

- **Server image:** `/healthz/deep` needs a server image that has that route. With an older image, the watchdog reports once that it cannot verify the site and then reports no outages until the image is upgraded. Use the image digest Honua gives you.
- **Imported web ACLs, including outside us-east-1:** the watchdog needs a per-stack token in the companion web ACL, which this stack does not create. Install with `WatchdogMode=Off`, and switch to `NotifyOnly` with a stack update after Honua has helped you add the token to that web ACL.
- **Pausing or removing it:** to pause it, use `WatchdogMode=Off` and keep it installed. `WatchdogMode=NotInstalled` removes it; the site-down alarm then relies on the public and origin checks, plus edge alarms where they are deployed. Removing it keeps its state parameter, and turning it back on later fails until you delete that parameter, so plan that change with Honua.

## Parameters

- `OperationKeyRingSecretArn` (empty): Empty generates the key-ring secret. Set it only to use a certificate secret you created as described in [Operation key ring](#operation-key-ring), and never clear it afterwards.
- `ServerImageUri` (empty): Empty runs the image the template version pins, which today is a pre-release image, so for this preview install always set it to the image digest Honua gives you. It must be a digest; the stack refuses a tag. A value you set stays until you change it. Running more than one task needs that release image.
- `WebAclArn` (empty): The `waf.yaml` output. Required outside us-east-1; leave empty in us-east-1 unless importing a companion for custom settings.
- `WebAclMetricName` (`HonuaWebAcl`): Copy the companion stack's output of the same name for imported-WAF metric configuration; use the metric output, not the web ACL ARN or resource name. In us-east-1, the stack selects its own metric automatically. Outside us-east-1, the main stack creates no WAF traffic alarms: supplying this parameter does not enable them. The `OpsEdgeAlarmSetup` output calls for a separate `ops-edge.yaml` deployment in us-east-1; arrange that additional operations setup with your Honua contact before relying on edge alarms.
- `NamePrefix` (`honua`): Prefix for resource names.
- `BucketNamePrefix` (`honua`): Prefix for the names of the Console and public-data buckets, 2 to 14 lowercase letters, digits or hyphens. Keep it unchanged on updates: a new value replaces the Console and public-data buckets, and the old buckets are retained and keep billing until you delete them.
- `CpuArchitecture` (`X86_64`): `ARM64` runs the server and Batch tasks on Arm-based Fargate. Every image you set, including `ServerImageUri` and `BatchImageUri`, must include the architecture you choose.
- `Size` (`Small`): Choose Small, Medium or Large as a starting configuration, then qualify it with your workload. These are planning presets, not measured capacity guarantees.
- `Availability` (`Standard`): One NAT gateway and single-AZ database. `High` uses at least two tasks, two NAT gateways and a Multi-AZ database; it adds AWS charges.
- `MinTasks` / `MaxTasks` (`-1` / `-1`): Follow the preset. Small/Standard starts with one task and permits two. Advanced overrides allow up to ten tasks; zero minimum is for controlled maintenance only. Tasks share state through the database, so several tasks need no other setting.
- `OpsNotificationEmail` (empty): A separate mailbox for operational alarms and budget notices. Empty sends them to `AdminEmail`. Required only with `IdentityProvider=External` when `AdminEmail` is empty. Confirm the subscription email after creation.
- `Protection` (`Contain`): Enables protection on install, including managed WAF rules, Anti-DDoS, Bot Control, private service endpoints, flow logs, HSTS preload and load-balancer deletion protection. Deletion protection is applied only after every other resource exists. These services add AWS charges. Watch reduces these controls; Strict also enforces GIS payload rules and requires `DomainNames`, so the stack refuses Strict on the `cloudfront.net` address. The preset also sets how long the stack's CloudWatch log groups keep logs: 30 days under Watch, 90 under Contain and 365 under Strict. Change the preset only through a reviewed stack update. For any imported web ACL, also review the companion WAF stack's protection settings.
- `DatabaseDeletionProtection` (true): Turn off only immediately before deleting the stack.
- `DomainNames` / `AcmCertificateArn` / `HostedZoneId` (empty): Your own hostnames (up to three). The certificate must be issued in us-east-1. With a Route 53 zone in the same account, the stack creates the DNS records.
- `IdentityProvider` (`Cognito`) / `AdminEmail` (required with Cognito): Creates sign-in and invites the first administrator, automatically adding them to the `admin` group. Invitations expire after seven days; your AWS administrator can resend them through Cognito. Self-registration is disabled; you create additional administrators and add them to `admin`. `External` uses your existing provider and invites nobody; `AdminEmail` is then only the notification address when `OpsNotificationEmail` is empty.
- `OidcAuthority` / `OidcClientId` / `OidcClientSecretArn`: Required only with `IdentityProvider=External`. Register a confidential authorization-code web client with `openid`, `profile` and `email` scopes. Store its plaintext client secret in Secrets Manager in the same account and region, encrypted with `aws/secretsmanager`. Sign-in remains subject to the recorded clean-install check before partner launch.
- `AdminCredentialAccess` (`Sealed`): Who can read the generated administrator API credential. Leave `Sealed`; `BreakGlass` is for recovery only (see [Recover administrator access](#recover-administrator-access)).
- `OidcRoleClaimType` (empty): External mode uses `roles` by default; set your provider's ID-token claim carrying `admin` or `administrator`. Cognito mode automatically uses `cognito:groups`.
- `EnableBatch` / `BatchImageUri` (off / empty): Adds AWS Batch capacity. Batch runs the server image, the same digest as the API, unless `BatchImageUri` names another server image digest from the same release. Do not set it to the GDAL worker image, which cannot run managed jobs. Managed geoprocessing jobs still run on the server tasks by default; sending them to Batch needs a reviewed template change, which we make with you. The server may submit and stop only jobs tagged `honua:stack` with this stack's name. A server image that submits untagged jobs is refused, and jobs submitted before the tag existed can no longer be stopped by the server, so drain Batch jobs before an update that adds the rule. Native GDAL workloads do not run on Batch.
- `ExistingVpcId` / `ExistingPrivateSubnetIds` (empty): Reuse your VPC: two private subnets in different supported Availability Zones, with outbound HTTPS through NAT or VPC endpoints. The VPC needs DNS resolution and DNS hostnames, an attached internet gateway, and enough free private IPv4 addresses for Fargate tasks and the CloudFront VPC origin. With the default `Protection=Contain`, also set `ExistingPrivateRouteTableIds` to every route table of those subnets, for the S3 gateway endpoint. Apart from that endpoint's route, the stack never changes your routes, subnets or NAT.
- `EnableConsole` / `ConsoleBundleVersion` (true / empty): Leave both at their defaults to serve the Console files the published template installs. `EnableConsole=false` installs the API only, without browser sign-in or approvals. Set `ConsoleBundleVersion` only to serve files you uploaded yourself under `console/VERSION/console/` in the Console bucket; a version you name always wins over the published files. If you switch Console off, a later update that switches it back on fails until you empty and delete the retained Console bucket.
- `BackupRetentionDays` (35): Daily AWS Backup recovery points for the database and files, kept for the chosen number of days. Exactly `0` turns them off, except under Strict, which keeps 35 days. Job outputs are excluded. RDS automated backups separately retain seven days.
- `CopyToVaultArn` (empty): An existing AWS Backup vault, for example in another region or account, that receives a copy of each recovery point. It needs backups on. A copy to another account also needs `CustomerKmsKeyArn` set when the database was created, AWS Organizations, and key and vault policies that share access. The stack refuses a copy to another account without `CustomerKmsKeyArn`; it cannot check the rest, so a missing policy shows up as failed copy jobs.
- `EnableVaultLock` (false): Locks the stack's backup vault in compliance mode, so recovery points cannot be deleted before they expire. It needs `BackupRetentionDays` from 7 to 365. Seven days after it is set, nobody in your account, including the root user, can remove the lock, and the recovery points keep billing after the stack is removed until they expire. Turn it on only when your retention policy requires it.
- `ApplicationDatabasePasswordGeneration` (empty): Leave empty at install. To rotate the application database password, do it in a quiet period: let running Batch jobs finish and pause submissions; store a new password in the `ApplicationDatabaseCredentials` secret, keeping its JSON shape `{"username":"honua_app","password":"..."}` and using letters and digits only (for example from `aws secretsmanager get-random-password --exclude-punctuation`); then immediately update the stack with a new value here (for example the date) and every other parameter unchanged. The update rewrites the connection secret and replaces the tasks; expect errors for a minute or two from old tasks. Check `/healthz/ready` and the service before resuming Batch submissions, because Batch jobs read the connection secret when they start. Editing the secret alone changes nothing. Use a new value for each rotation, and if the update rolls back, keep the stored password and repeat the update with another new value.
- `WatchdogMode` (`NotifyOnly`): The independent watchdog described above. Set `WatchdogMode=Off` for any imported web ACL, including outside us-east-1, until its token is in place. Use `NotInstalled` to omit it entirely. Do not select `Act`; the acting mode is not part of this install.
- `AllowedBrowserOrigins` (empty): Up to five HTTPS origins, comma-separated and written exactly as browsers send them (`https://host`, or `https://host:port` for a port other than 443; no paths or wildcards), whose web pages may call this install from another site, for example your own map application. Empty allows same-origin requests only.
- `EnablePublicData` (false): Adds a retained, private S3 bucket that the install serves read-only at `/data/*` for static files such as PMTiles and GeoParquet, with byte-range requests. Upload files under the `data/` key prefix with their Content-Type (the `PublicDataBucketName` and `PublicDataUrl` outputs name the bucket and address). Turning it on also asks the server to publish. A server that supports public export copies only what an anonymous caller could already read, then removes that file and asks CloudFront to drop it when the access is taken away. A server without that support ignores the switch. A copy CloudFront already served cannot be recalled. Anyone who has the address can read those files without signing in, from any web page: `GET` and `HEAD` return `Access-Control-Allow-Origin: *` and never send credentials. `AllowedBrowserOrigins` still governs the API only, not `/data`. Store only data you intend to publish.
- Object storage Connections: the server can read a bucket you choose. Console offers a quick-create stack, from the `connection-role.yaml` published beside this template, that creates one read-only role named `honua-connection-<id>`. That role trusts only this install's task role, and only with the external id Console supplies, and it carries the tag `honua-installation` set to this stack's GUID. The task role assumes only roles named `honua-connection-*` that carry this install's tag. The bucket may be in this account or another. Delete that connection stack to revoke access. If the task role is replaced, update the connection stack with the new ARN or the Connection fails.
- `EcrRepositoryArns` (empty): Every private ECR repository your images come from, comma-separated. Required for private ECR images; without it the tasks cannot pull them.
- `WebAclArn` also supports a companion web ACL in us-east-1 when you need custom WAF settings. The main stack's own web ACL uses the fixed per-IP figures in the paragraph after this list and has no country allow list. `waf.yaml` starts from the same figures. Configure different figures or a country allow list there, then import its outputs into the main stack. Contain and Strict require the companion to include Anti-DDoS and Bot Control as well as the managed rules; update the companion first.
- `CustomerKmsKeyArn` (empty): Optional encryption-key override for application resources and the database, in the same account and region. Empty uses the rotating stack key. Review the required service key policies before supplying your own key, and set it at installation: a later change replaces the database.
- `AiProvider` (`None`): Design-partner default. Leave None unless you turn the optional Studio assistant on. `Bedrock` or `CustomerKey` are the only other values. The other assistant parameters apply only then: the `openai` default of `AiCustomerKind` does not call a provider while this stays None. See [Optional Studio assistant](#optional-studio-assistant).
- `AiBedrockModelId` (empty): Regional Bedrock foundation-model id. Required with `AiProvider=Bedrock`. Inference profiles are refused.
- `AiInvocationLogBucketName` (empty): Existing private encrypted bucket in this account and region for Bedrock invocation logs. Required with `AiProvider=Bedrock`. The stack does not create or delete this bucket.
- `AiCustomerKind` (`openai`): `openai` or `anthropic`. Used only with `AiProvider=CustomerKey`.
- `AiCustomerModel` (empty): Model id the provider account may use. Required with `AiProvider=CustomerKey`.
- `AiCustomerSecretArn` (empty): Secrets Manager secret in this account and region whose entire value is the provider key. Required with `AiProvider=CustomerKey`. Never put the key in a parameter.
- `AiWorkloadDataClassification` (empty): Classification you approve for disclosure to the selected model and destination. Required when `AiProvider` is `Bedrock` or `CustomerKey`.

Application rate limiting is on for every install, and the template has no parameter for it. The current server image allows 1,000 requests per minute for each address the trusted forwarding hop reports, or for each signed-in subject, and counts that separately on each task. Query, upload and metadata routes are tighter: 100, 10 and 200 per minute. A request over a limit receives `429` from the application, which is separate from the web ACL. Per IP per five minutes, the stack's own web ACL blocks every request above 2,000; feature, map and image queries and feature-item reads above 600; edits above 120; sign-in above 120; and geoprocessing above 60. It challenges browser page loads above 1,000 in that window. Those figures are fixed. People who share one address share the uncached allowance.

In us-east-1, the stack creates a budget notice threshold from `Size` and `Availability`; it is not a spending cap or a bill estimate. Activate the `HonuaStack` cost allocation tag in AWS Billing for costs to count toward it. Budget notices go directly to the operations email; operational alarms require confirmation of the SNS subscription. Outside us-east-1 the stack sends no budget notices. Set additional budgets in your AWS account from your own estimate.

## Optional Studio assistant

Leave `AiProvider=None` unless you mean to send Studio chat to a model. None creates no assistant policy, Bedrock endpoint or invocation-logging setup. You operate any assistant you turn on, in your AWS account. AWS bills the resources it creates, and with CustomerKey your provider bills the model use. Honua does not host the model and does not receive the prompts. Agents you run yourself can still use Honua's MCP surface; those clients, and any model provider they call, can see the data they retrieve. You choose that provider and its terms.

Selecting `Bedrock` or `CustomerKey` approves disclosure of `AiWorkloadDataClassification` to that destination and model for Studio chat. Changing the model, region or classification changes that approval. With Bedrock, AWS charges you for the model use, a private interface endpoint in both private subnets (created whenever Bedrock is selected, including when `Protection` is Watch), and the invocation logs in the bucket you prepared. With CustomerKey, the provider bills the model use and AWS charges you only for the outbound traffic.

**Amazon Bedrock.** Set `AiProvider=Bedrock`, `AiBedrockModelId` to a regional foundation-model id, `AiInvocationLogBucketName` to a bucket you prepared, and `AiWorkloadDataClassification`. Enable that model in Bedrock, in a region that offers on-demand inference, before you create the stack. The server uses its task role, calls only that model, and reaches Bedrock through a private endpoint. No model API key is stored.

Invocation logging applies to the whole account in that region, including calls from other applications. The stack adopts an identical logging configuration and fails rather than replacing someone else's. It does not change your bucket or key policy. Prepare the bucket as Amazon describes for [Bedrock model invocation logging](https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html): block public access, set retention, and allow `bedrock.amazonaws.com` to write under `honua-model-invocations/AWSLogs/ACCOUNT_ID/BedrockModelInvocationLogs/*` with `aws:SourceAccount` and the regional Bedrock `aws:SourceArn`. For a customer-managed key, also grant Bedrock `kms:GenerateDataKey`. Turning the assistant off or deleting the stack leaves that logging in place. Your bucket is not part of the stack. Operators in your account can read the logs, including prompt and response text, so do not send data you cannot retain.

**A key in your provider account.** Set `AiProvider=CustomerKey`, `AiCustomerKind` to `openai` or `anthropic`, `AiCustomerModel`, `AiWorkloadDataClassification` and `AiCustomerSecretArn`. The secret's entire value is only the provider key. Prefer the default Secrets Manager key. If the secret uses a customer-managed key, set `CustomerKmsKeyArn` to that key at installation and allow the task execution role in the key policy: a later change of `CustomerKmsKeyArn` replaces the database. Never put the provider key in a parameter, output or log. The execution role can read only that secret, and only the server container receives it. After you rotate the secret, start a new ECS deployment so tasks pick up the value. This path needs a route to the public internet, such as a NAT gateway, to reach `https://api.openai.com/v1` or `https://api.anthropic.com`. An existing VPC that has only VPC endpoints cannot reach the provider. It creates no Bedrock permissions, endpoint or invocation logging. The provider sees the request content and bills the model use; review that account's retention before you enable it.

Before the first assistant request, an administrator runs the server operation `admin.ai.admission.initialize`, reads the generation, revision and epoch it reports, then runs `admin.ai.admission.resume` with those values. These are administrator operations on the server, not stack parameters. Initialization leaves admission stopped, and startup does not resume it. The steps are in the server's [AI invocation admission](https://github.com/honua-io/honua-server/blob/trunk/docs/reference/configuration/ai-execution-admission.md) reference. Attempt and concurrency limits are not a token budget or a spending cap. Studio on Bedrock has no financial admission control.

## What you pay AWS

AWS bills you directly for the resources in your account. Plan for these charges before you approve the install:

- ECS Fargate tasks, the RDS database, the load balancer and NAT gateways.
- File, job-output, Console and public-data object storage, CloudWatch logs, metrics and alarms, and database and file backups.
- KMS encryption, CloudTrail audit records, GuardDuty protection and notification services enabled by the template.
- CloudFront traffic, data transfer, and AWS WAF rules and requests.
- With default sign-in, Cognito Plus user activity and threat protection, and its client-secret Lambda and Secrets Manager storage.
- The watchdog's Lambda invocations, metrics, alarms, logs, probe secret, code storage and WAF rule, unless you remove it (`WatchdogMode=NotInstalled`).
- When the Studio assistant uses Bedrock: model use, a private interface endpoint in both private subnets (also when `Protection` is Watch), and invocation-log storage in the bucket you prepared. When it uses CustomerKey, AWS charges outbound traffic to the provider, and the provider bills the model use. The default `AiProvider=None` adds neither.

Your bill depends on the region, resource sizes, traffic and retention settings. Two NAT gateways, a Multi-AZ database, more tasks and Batch jobs add charges. The default Contain protection also enables private service endpoints, flow logs, Bot Control and Anti-DDoS. Watch disables these controls in the main stack's own resources. An imported companion web ACL has separate settings: its Anti-DDoS is enabled by default even in Watch, and Bot Control can remain enabled independently, so review both stacks when estimating charges. Custom WAF settings require the companion stack. Retained encryption keys and data continue to incur charges after stack deletion. Estimate your chosen configuration with the [AWS Pricing Calculator](https://calculator.aws/) and monitor the resources in your AWS account.

## Recover administrator access

Administrators sign in through Console and create API keys from that session. The stack also generates an administrator API credential that the server needs at start-up. It carries full administrator rights without sign-in or a second factor, so it is sealed by default: with `AdminCredentialAccess=Sealed`, AWS refuses to return the value behind `AdminSecretArn` to anyone but task start-up, and the server accepts that credential only from loopback inside the task. Every container in the task shares loopback; only the server container is given the credential. It cannot approve agent-proposed changes, and a caller on the network cannot use it while it is sealed.

Use it only when sign-in is unavailable and an administrator must act. Update the stack with `AdminCredentialAccess=BreakGlass`. That opens the secret's access policy and replaces the server tasks so they accept the credential over the network. CloudTrail records the update. Read the value without printing it and send it as the `X-API-Key` header. Keep it out of tickets, screenshots and shell history. When sign-in works again, replace the value with a random one of at least 16 characters that has an upper-case letter, a lower-case letter, a digit and a punctuation character (the server refuses to start otherwise), start a new deployment of the ECS service so tasks pick up the new value, and update the stack back to `Sealed`. Returning to `Sealed` replaces the tasks again and returns the credential to loopback only. Plan this recovery with your Honua contact.

## Use your own domain

Leave the domain parameters empty to use the CloudFront address. To add a domain later, issue an ACM certificate in **us-east-1** that covers every hostname, update the stack with `DomainNames` and `AcmCertificateArn`, then point each hostname at the `CloudFrontDomain` output (a CNAME, or an alias at the zone apex). With a same-account Route 53 zone, also set `HostedZoneId` and the stack creates the records; in us-east-1 it can also create and validate the certificate for you. With External mode, register `https://YOUR_FIRST_DOMAIN/admin/auth/callback` with your identity provider before the update. Cognito mode updates the callback automatically.

## Upgrade

Take and verify a database snapshot first. Then update the stack with the new `ServerImageUri` digest (and the new `BatchImageUri` when the release notes say it changed), or with the newer template link Honua sends you, which brings its own watchdog code and Console files. Outside us-east-1, update the companion `waf.yaml` stack first. Review the change set, and execute it. Console files from earlier versions stay in the Console bucket for rollback. Database migrations run when the new server starts. Rolling back the image does not roll back a migration, and rollback is supported only to rc.2 or later releases whose migrations allow it, so keep the snapshot until the upgrade is verified.

Upgrading an install created before deferred deletion protection may briefly leave the database unprotected. The update removes the template's own database protection setting, then the final step turns protection back on.

When updating an existing external-provider stack to this template, explicitly set `IdentityProvider=External` to preserve sign-in; existing OIDC values are ignored in Cognito mode. Changing `AdminEmail` replaces the bootstrap user; when `OpsNotificationEmail` is empty it also moves the alarm subscription to the new address, which receives nothing until its owner confirms the new subscription email. Image and Console upgrades preserve the Cognito pool and client, but switching away from Cognito deletes its user directory. Verify administrator access before retiring the old provider, and export needed user metadata first. Stack rollback cannot restore deleted users or passwords.

An install created before the retained log groups carried the stack ID moves new logs and the watchdog state to the new names on update. The old log groups and parameter keep their earlier contents until you delete them. The new state parameter starts empty, so the watchdog's seven-day action history restarts and notices still waiting are not sent; if the watchdog took a recovery action in the past week, set `WatchdogMode=NotifyOnly` for that update and return to `Act` seven days later. An install created with your own key-ring certificate keeps `OperationKeyRingSecretArn` set on every update.

When you update with the AWS CLI or API, a parameter you leave out takes the template's current default, not your previous value: pass every parameter, using `UsePreviousValue` for those you keep. In particular, an omitted `OpsNotificationEmail` moves alarms to `AdminEmail`, and an omitted `WatchdogMode` installs the watchdog in `NotifyOnly`. If you previously used `EnableWatchdog=false`, remove that retired key and explicitly pass `WatchdogMode=NotInstalled` to keep it absent. In the console, check these values on the parameters page before you continue.

A newer template can also remove parameters, and AWS refuses a parameter file that still names one. This template version no longer has `TaskSize`, `DatabaseClass`, `TwoNatGateways`, `DatabaseMultiAZ`, `DatabaseKmsKeyArn`, `PostgresClientImageUri`, `EnableBackupPlan`, `LogRetentionDays`, `ExistingGuardDutyDetectorId` or any agent parameter, among others: sizes follow `Size`, the second NAT gateway and Multi-AZ database follow `Availability`, and the database key follows `CustomerKmsKeyArn`. A stack that set one of them changes to the preset value on that update, so review the change set and reject it if it replaces the database. A stack that set `EnableBackupPlan=false` turns AWS Backup on with the default retention unless that update passes `BackupRetentionDays=0`.

The current template also retires individual WAF, endpoint, flow-log, load-balancer protection, budget and backup tuning parameters. Remove retired keys from your parameter file and compare every supplied key with the new template before updating. Bot Control, Anti-DDoS, private endpoints, flow logs and load-balancer deletion protection now follow `Protection`: on in Contain and Strict, off in Watch. A Watch install that depended on private endpoints must choose Contain or provide its own endpoints or NAT before updating, so tasks can still reach ECR, Secrets Manager, Logs and S3. Custom WAF limits or country lists require importing a companion web ACL, including in us-east-1; otherwise an update replaces them with the fixed defaults. A Contain or Strict companion that previously disabled Anti-DDoS gains its charges and browser challenges on update.

Log retention now follows `Protection` and replaces `LogRetentionDays`, whose default was 90 days. An update applies the preset's retention to every stack log group, and CloudWatch deletes older events at once: a Watch install drops from 90 to 30 days, and an install that set its own value moves to its preset. Export any logs you must keep before updating.

RDS automated backup retention is now fixed at seven days; updating an install with longer retention loses the older automated backups and restore range, so take a manual snapshot first. The template fixes the backup window at 08:00–09:00 UTC and maintenance at Sunday 09:30–10:30 UTC. AWS Backup now runs daily, excludes job outputs and retains copies for `BackupRetentionDays`. Optional compliance-mode Vault Lock has fixed bounds of 7–365 days: **do not apply this template update to a vault whose lock was finalized with different bounds**, because a finalized compliance lock cannot change. Review these changes with your AWS administrator before executing the change set.

## Remove the install

- **Step 1.** Drain any running Batch jobs. Export any needed Cognito user metadata and plan account recovery: stack deletion removes its user directory and sign-in client.
- **Step 2.** Save the bucket names, `DatabaseInstanceIdentifier`, `BackupVaultName`, the ECS cluster name, encryption-key identifiers and the secret ARNs from the stack's Outputs and Resources. You need them to clean up what is retained.
- **Step 3.** Through an approved stack update, set `Protection=Watch` and `DatabaseDeletionProtection=false`. Wait for `UPDATE_COMPLETE`. That update turns load-balancer deletion protection off and turns database deletion protection off. Deleting while `Protection` is still Contain or Strict leaves load-balancer deletion protection on, so confirm both are off before you delete.
- **Step 4.** Delete the main stack, then delete any separately created `waf.yaml` companion stack in us-east-1, including a companion used for an install in us-east-1. Always delete the companion after the main stack.

Compute, networking, the load balancer, CloudFront and WAF are removed. To protect your data, these are **kept and keep billing** until you delete them yourself:

- a final RDS snapshot (find it in RDS Snapshots by the saved database identifier);
- the S3 buckets, including all object versions, and the Console bucket with every Console version unpacked into it;
- the generated database credential and connection secrets, the administrator credential, the connection-encryption secret and the audit-chain key secret, and the operation key ring secret (generated, or your own). Preserve the audit-chain key while audit rows exist. The Cognito client secret is removed with the stack;
- the stack encryption key and any customer-owned keys. Keep every key needed to decrypt retained snapshots, backups, buckets or secrets; schedule key deletion only after those recovery and retention obligations end;
- the AWS Backup vault and its recovery points. With `EnableVaultLock=true` you cannot delete recovery points before they expire, so they keep billing until then. Copies in a vault named in `CopyToVaultArn` are yours to manage and the stack never changes them;
- a GuardDuty detector the stack created, and the created CloudTrail trail and its bucket and delivery policy. These can protect other workloads, so review their account-wide use before removing them. A detector that already existed is never changed or deleted;
- the application, Batch, Console install and watchdog CloudWatch log groups. The template retains watchdog log groups even when the watchdog is disabled;
- the watchdog's code bucket and its object versions, its probe secret and its state parameter in Systems Manager Parameter Store;
- Bedrock invocation logging, when you turned the assistant on. The stack does not remove that regional logging configuration or the bucket you prepared for it;
- log groups AWS creates outside the stack, which keep logs indefinitely by default: `/aws/rds/instance/DB_INSTANCE_ID/postgresql`, `/aws/rds/instance/DB_INSTANCE_ID/upgrade` and `/aws/ecs/containerinsights/CLUSTER_NAME/performance`. The stack's log retention does not apply to them; set their retention after install.

Delete them once your recovery and retention obligations are met. The retained log groups and the watchdog state parameter carry the stack's ID as well as its name (`/honua/YOUR_STACK_NAME/STACK_GUID/...`, where `STACK_GUID` is the first segment of the GUID in the stack ID), so a new install can reuse a deleted stack's name. Certificates and DNS records the stack created are removed; your own certificates and DNS records are not.

## Clean up a failed creation

A current template applies deletion protection only after every other resource exists, so a failed first create is not blocked by deletion protection. If creation still stops in `ROLLBACK_FAILED`, inspect the stack's Events and Resources before deleting anything. This state does not support the stack update used in normal teardown; see the [AWS stack status reference](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/view-stack-events.html#stack-status-codes).

A stack an earlier template left in `ROLLBACK_FAILED` can still hold a protected database and a protected load balancer. When Events name deletion protection as the blocker, turn deletion protection off on that database and on that load balancer, and only on the failed install. In the RDS console, select that database from Resources and modify it to turn deletion protection off. In the EC2 console in the deployment region, select that load balancer, open **Attributes**, choose **Edit**, turn off **Deletion protection**, and choose **Save changes**. Follow [AWS's load-balancer attribute instructions](https://docs.aws.amazon.com/elasticloadbalancing/latest/application/edit-load-balancer-attributes.html#deletion-protection) and [RDS deletion protection](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_DeleteInstance.html).

Resolve any other resource deletion errors shown in Events, then retry **Delete** on the failed CloudFormation stack. Do not delete resources belonging to another stack or shared account protection. Check the retained-resource list above after cleanup; retained data, keys and backups can still incur charges. Fix the original creation error before launching a replacement stack; it can reuse the failed stack's name.

## Troubleshoot

- Start with the stack's **Events** tab. The lookup function writes a short reason and logs to `/honua/YOUR_STACK_NAME/prefix-lookup`.
- **The stack fails on `ConsoleBundle`:** the cause is the single line in the `/honua/YOUR_STACK_NAME/STACK_GUID/console-deploy` log group.
- **Image pull errors:** check the image URI, its architecture and registry access through the NAT gateway.
- **The server never becomes healthy:** read the application logs (the `ApplicationLogsUrl` output) for database, PostGIS or migration errors before changing health checks.
- **403 from the load balancer:** it received a request without the distribution's secret header. A 403 can also come from a WAF rule, so check the WAF logs first. Do not open the load balancer's security group to the internet.
- **429 from the application:** the per-task limit in [Parameters](#parameters), not the web ACL. A web ACL block is a 403. Check whether many callers share one address before changing anything; the template has no limit parameter.
- **Certificate stuck pending:** check the zone delegation, that the certificate covers every hostname, and CAA records (allow `amazon.com`).

Send stack events and log excerpts to your Honua contact, never secret values.
