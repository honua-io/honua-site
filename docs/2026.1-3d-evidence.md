# 2026.1 3D evidence publication

Issue: [site #234](https://github.com/honua-io/honua-site/issues/234).
Release promise: the quality contract §14 requires current public evidence and a
coherent supported/preview/experimental matrix. This publication corrects that
promise without adding hosted 3D depth to 2026.1.

The server dependency [#3279](https://github.com/honua-io/honua-server/issues/3279)
is closed. Its matching capability-truth [PR #3605](https://github.com/honua-io/honua-server/pull/3605)
merged on 2026-08-29, before site PR #247 is made ready.

These are source attribution counts, not passing execution results, CITE results,
or exact-candidate certification. The generated pages explicitly say so. Their
Date column records the site snapshot date, not a runtime test date.

`data/scene-evidence.v1.json` retains reviewed release boundaries through future
syncs. It overrides the stale 3D Tiles key description's “SceneServer” wording
with the protocol's `/scenes/{sceneId}/tileset.json` route. Editions and counts
remain server-derived. Scene pages cite `matrixUrl` from that overlay. They do
not copy the sync fetch URL: `scripts/sync-capabilities-data.mjs` defaults
`CAPABILITY_MATRIX_URL` to server `trunk`, and using that URL would replace the
pin. I3S is an Enterprise metadata preview with HTTP 402 when the
`serve.i3s-scene` entitlement is unavailable; production does not advertise
renderable geometry. LAZ/COPC and projected scene input need a configured
worker and return HTTP 400 without one. Experimental scene ingest does not
demote GA `pcloud.translate`.

Public pages label those edition values as 2026.2 intent. 2026.1 ships with
licensing disabled, so the values are the server vocabulary, not a claim that
2026.1 enforces edition gating. The 402 and 400 results are the pinned route
contract for a missing entitlement or worker.

3D scenes remain Experimental, opt-in, outside GA compatibility and SLA. The
Maui sample remains MapLibre 2.5D extrusions/raster terrain. No hosted I3S demo
URL, governed 3D client receipt, Cesium terrain claim, or runtime fixture result
is invented. Hosted candidate data/live scene endpoints, broader rendering,
and the slice-22 presentation page remain deferred to 2026.2 as #234 specifies.
Independent elevation analysis is described separately from scene rendering.

## Verification

The tests in `scripts/capability-catalog.test.mjs` check the public labels,
the pinned matrix URL, absence of fabricated live-scene links, and editions/counts
against the separately authored protocol truth table above. They check HTTP 402/400
wording, the correct 3D Tiles route, Experimental scope, and preservation of the
2.5D demo. These are documentation projection tests; no server execution correctness
is claimed. The retired workflow page is a bookmark notice, not a capability receipt;
that behavior is covered by `scripts/sync-capabilities-data.test.mjs`.

Local validation on 2026-09-26 passed 124 Node tests (zero skips) and the
complete Pages validation job, including its remote package/source checks, build,
and emitted artifact checks. The live NuGet index served Honua.Sdk 1.10.0, so
the public package claim moved with it. That is registry reconciliation, not a
3D capability change. Run the existing job from `.github/workflows/pages.yml`, including:

```sh
node --test scripts/*.test.mjs edge/cloudfront-template.test.mjs
node scripts/gen-capability-catalog.mjs --check
node scripts/sync-capabilities-data.mjs --check
node scripts/validate-capability-links.mjs
node scripts/validate-slices.mjs
node scripts/validate-site-claims.mjs
node scripts/validate-internal-links.mjs
./scripts/build-dist.sh
node scripts/validate-slice-voice.mjs
node scripts/validate-slice-concepts.mjs
```

The reviewed sync removes retired upstream keys and keeps the 114-key catalog
from that commit. Reproducing it requires the pinned artifacts, not the default
trunk URLs:

```sh
CAPABILITY_MATRIX_URL=https://raw.githubusercontent.com/honua-io/honua-server/eb70bab24fc102fee41b1bf2091d17b4e548f443/docs/gis/data/capability-matrix.v1.json \
CAPABILITY_KEYS_URL=https://raw.githubusercontent.com/honua-io/honua-server/eb70bab24fc102fee41b1bf2091d17b4e548f443/docs/gis/data/capability-keys.v1.json \
node scripts/sync-capabilities-data.mjs
node scripts/gen-capability-catalog.mjs
```

An unpinned sync may refresh other capabilities from current server trunk. It
still writes the pinned scene provenance URL. The catalog test rejects edition
or count drift from the table above, so a newer server count cannot ship under
this pin. Live server trunk is not a silent substitute for the reviewed table.
