Client & SDK version compatibility

← Back to proof & claims

Which Honua SDK versions are supported against which server versions, which specific version pairings are known-bad, and the policy-approved version to upgrade to. This page answers the most repetitive compatibility question — "is my client version OK against this server?" — from a single, versioned source of truth. For which Esri REST operations and Esri clients Honua implements (a different question — operation coverage, not version windows), see the Esri → Honua compatibility matrix.

This matrix is generated, not hand-maintained. The SDK table below is rendered from the versioned compatibility policy compatibility-policy.v1.json, whose canonical home is honua-io/honua-support (honua-support#42). A synced snapshot lives in this repo at data/compatibility-policy.v1.json, and scripts/gen-compatibility-matrix.mjs regenerates the table from it, so the page cannot drift from the policy without a visible diff.

Supported SDK versions by server family

Each row is one first-party SDK. A known-bad window is a specific (SDK version, server version) pairing the policy marks as incompatible; it is checked before the supported window. The policy-approved upgrade target is the highest version support has cleared against the deployed server family — deliberately not necessarily the newest release (for example, sdk-js 7.x is a major that is not approved against server 2.x, so the approved target stays on 6.x).

Version ranges use space-separated comparators (>=, >, <=, <, =); every comparator in a range must hold for the version to match. All supported windows currently target the server 2.4.x–2.x family; the server ranges are quoted verbatim from the policy so they stay correct as the policy evolves.

If your SDK is in a known-bad window

Every known-bad window carries a guided fix: the symptom, why the pairing is incompatible, and the exact policy-approved version to move to. The reference pattern is published as a KB article:

  • KB-COMPAT-0001 — sdk-js 5.x is behind a known-bad window; upgrade to the policy-approved target (the reference pattern; KB-COMPAT-0002 for sdk-dotnet 3.x and KB-COMPAT-0003 for sdk-python 1.x follow the same shape).

Third-party desktop clients (ArcGIS Pro, QGIS)

The versioned policy above governs Honua's first-party SDKs. Third-party desktop clients are not pinned to SDK-style version windows in the policy; their compatibility is tracked as operation-level evidence, because they consume Honua through the standard protocol surfaces rather than a Honua-versioned client library.

Server-version windows for third-party desktop clients are intentionally not asserted here: the compatibility policy does not carry them, and this page does not hand-invent version data. When the policy adds third-party client windows, they will appear in the generated table above automatically.

Keeping this in sync

The policy in honua-support is the single source of truth. To refresh this page after the policy changes:

gh api repos/honua-io/honua-support/contents/compatibility/compatibility-policy.v1.json \
  --jq '.content' | base64 -d > data/compatibility-policy.v1.json
node scripts/gen-compatibility-matrix.mjs        # regenerate the table above
git diff                                          # review, then commit

This resync is manual today; closing the loop automatically (a scheduled check that opens a PR when the upstream policy moves, or a CI check that fails when the snapshot or generated table is stale) is a tracked follow-up. See data/README.md for the full contributor note.
