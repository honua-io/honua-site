Use an agent that can run commands on your development machine. The guide starts a local evaluation with sample data from a digest-pinned preview image; it does not deploy to your cloud account or qualify that image for production.

AWS, through the operator.

Register the honua-devops operator as an MCP server first. Its release ships self-contained binaries for Linux, macOS and Windows and a container image; download the archive for your machine, check its digest, and register it with your MCP client. In MCP mode your client's model does the reasoning, so the operator needs no model provider key.

The commands use Claude Code; Codex CLI and other MCP hosts register the same executable with --mcp. Full quickstart: QUICKSTART-MCP.

Then paste the prompt

It pins the agent to the honua-iac ECS/Fargate stack, the qualified 2026.1 target, makes it show you the account, region, resources, cost drivers and plan digest before anything is created, and forbids apply until you approve that exact plan. The operator's own gates enforce the same rules: one saved plan, an approval receipt, no IAM users or long-lived keys, and a verified install handoff before the server counts as ready.

Operator deployment guideDeploy on AWS and Azure

honua-iac also ships a qualified AWS Lambda stack and Azure previews; the agent path stays on ECS/Fargate until their first-install workflows are qualified. How the operator is scored: multi-model operator evals.

1 · Register the operator
VERSION=v2026.1.0
ASSET=honua-devops-linux-x64.tar.gz   # or osx-arm64 / osx-x64 / win-x64 (.zip)

gh release download "$VERSION" --repo honua-io/honua-devops \
  --pattern "$ASSET" --pattern "$ASSET.sha256"
sha256sum -c "$ASSET.sha256"          # macOS: shasum -a 256 -c

mkdir -p ~/.local/share/honua-devops
tar -xzf "$ASSET" -C ~/.local/share/honua-devops

claude mcp add honua-devops -- ~/.local/share/honua-devops/Honua.DevOps.Agent --mcp
claude mcp list                       # honua-devops should report its tools
2 · Paste into your MCP client
Deploy Honua into my AWS account with the honua-devops operator and the honua-iac Terraform stacks.

Use the honua-devops MCP tools registered in this session: describe_environment, provision_infrastructure, install_handoff and verify_install_handoff. If they are not registered, stop and walk me through the registration steps in https://github.com/honua-io/honua-devops/blob/trunk/docs/QUICKSTART-MCP.md. Do not improvise a different install path.

Read the operator deployment guide before planning: https://github.com/honua-io/honua-iac/blob/trunk/docs/operator-deployment.md. Target AWS ECS/Fargate (the aws stack), the qualified 2026.1 target, at the small preset unless I say otherwise. Do not choose Azure, EKS, Helm or a mixed topology.

Before anything touches my account: tell me which AWS account and region my credentials resolve to, confirm Terraform 1.5 or later (1.10 or later for S3 state locking), and say whether we are on the disposable-development path (local state) or the governed path (remote state, short-lived OIDC identity, one exact saved plan). Recommend the governed path for anything shared or long-lived, and explain what its bootstrap steps create.

Produce the Terraform plan and show me the resources it will create, the cost drivers that keep billing afterwards (RDS PostGIS, Fargate tasks, load balancer, NAT, storage), and the plan's approval digest. Apply nothing until I approve that exact plan, and never regenerate a different plan after approval. Never create IAM users or long-lived access keys. Never print secrets, passwords, state files or credentials into the chat.

After apply: capture honua_url and the database endpoint, run the guide's health checks, write the install handoff and verify it. Provisioning success alone does not mean the server is ready; only the verified handoff does. Then show me how to point my MCP client at the installed server's /mcp endpoint for day-2 operations.

If anything fails, diagnose it and report the actual error. Do not retry destructive operations, delete state, or tear down resources without asking me first.

Finish with: target, account and region; the honua-iac and honua-devops versions used; the plan digest and apply receipt; endpoints; the checks performed; and the documented teardown command.
