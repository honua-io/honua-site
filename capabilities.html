WORK WITH YOUR DATA

Databases & warehouses.

Publish existing database tables as live layers without copying their data. PostGIS supports full read/write workflows; other providers have read-only or experimental scope, as shown below.

PostgreSQL / PostGIS ↗

Full read/write

Spatial data, edits, query statistics, analytics, and native spatial output.

SQL Server ↗

Read/query

Serve geometry and geography tables from an existing database.

DuckDB ↗

Read-only

Embedded analytical and reference data without another database service.

MySQL / MariaDB ↗

Read/query

Serve existing spatial tables through the provider’s query interface.

Oracle ↗

Experimental
Read/query

SDO_GEOMETRY support; use a non-Native-AOT build.

Amazon Redshift ↗

Experimental
Read/query

Native GEOMETRY and GEOGRAPHY through the warehouse provider.

Snowflake ↗

Experimental
Read/query

Read spatial warehouse tables; use a non-Native-AOT build.

Databricks ↗

Experimental
Read/query

Read from a SQL Warehouse through the Statement Execution API.

Experimental providers are separate from the supported read/query paths. Provider reference ↗

FILES, STREAMS & OBJECT STORAGE

Cloud-native formats. Familiar files.

See which formats you can import, register in place, produce, or request as query output.

Cloud-native feature data

Compact formats for analytical datasets and query results.

  • GeoParquet ↗File import · query output
  • GeoArrow / Arrow IPC ↗Query output · spatial columnar data
  • FlatGeobuf ↗File import · query output

Cloud imagery & tile archives

Publish imagery and tiles from files or object storage.

  • COG / GeoTIFF ↗Raster import · registered cloud tile sources
  • PMTiles ↗Archive · publish · serve with HTTP ranges
  • MVT / TileJSON ↗Vector tiles · tile source metadata

Multidimensional & scientific data

Register datacubes or convert scientific sources for coverage access.

  • Zarr v2 / v3 ↗Store registration · coverage subsets
  • NetCDF4 / HDF5 ↗URL registration · conversion to Zarr
  • GRIB / GRIB2 ↗URL registration · conversion to Zarr

NetCDF4, HDF5, and GRIB use the documented GDAL-to-Zarr path and require a reader-enabled build. Coverage release scope remains separate.

Vector & tabular files

Bring in familiar datasets and export through the documented file or query paths.

  • GeoJSON ↗File import · query output
  • GeoPackage ↗File import · file export
  • Shapefile (ZIP) ↗File import · file export
  • CSV ↗Coordinate / WKT import · file and query output

GPS, geometry & geodatabase files

Import tracks, interchange files, geometry text, and packaged databases.

  • GPX ↗File import
  • KML / KMZ ↗File import · map-service KML output
  • WKT ↗Geometry import
  • File Geodatabase (.gdb.zip) ↗Packaged file import

Query, map & image outputs

Choose the response format that fits your client or downstream workflow.

  • JSON / Esri JSON / GeoJSON ↗Feature-query responses
  • Protobuf / PBF / Geobuf ↗Binary feature responses
  • GML / CSV ↗Standards-based feature-query output
  • PNG / JPEG ↗Map images · georeferenced raster import with world files
