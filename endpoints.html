Demo endpoints: one of everything on demo.honua.io

One row per protocol the demo server enables. Each row gives the capability key, one URL you can copy into a client, the client that speaks it, the demo or sample that uses it, and a status check your browser runs against the live server when this page loads.

Waiting to start checks.

Rows come from data/demo-endpoints.v1.json. Paths for the seeded services come from the server's own demo-services.v1.json ↗, and the on/off state of each capability comes from its capability manifest ↗.

How to read the status column

  • Live The request answered and the body looked right: JSON with the expected field, an XML capabilities document, a PNG with drawn pixels, a vector tile, or a PMTiles header.
  • Degraded The server answered, but the body was not what a client needs, for example a blank image, an empty tile, or rate limiting.
  • Not live An error status, an error body behind HTTP 200, a network or CORS failure, or no answer within 8 seconds.
  • Off on demo The server ships the surface and its manifest reports it switched off on the demo.
  • Not browser-probeable A browser cannot make this request, so the page does not guess. The reason is in the row.
